- **TE&IV's store, O-RAN-SC smo-teiv 0.3.0, in the stack: compose profile `teiv` and the chart's `teiv` (plan task S3.23, ADR 0013). Off by default.** `./scripts/init_secrets.sh && docker compose --profile teiv up -d --build` builds smo-teiv from its pinned 0.3.0 tag with TE&IV's model extension (`teiv/`; O-RAN-SC publishes no 0.3.0 image) and starts its database, its ingestion and its exposure, with the profile `kafka`'s broker, which it shares (topic `smo.teiv.ingestion.v1`). New secret file `secrets/teiv_db_password` (`init_secrets.sh` makes it) and volume `smo_teiv_pgdata`. Nothing else of the stack can reach smo-teiv's database or API (an internal network `teiv`; no host port). **Chart:** `teiv.enabled` (false) runs `<image.registry>/smo-teiv:0.3.0-ext` and `smo-teiv-db:0.3.0-ext`, which `.github/workflows/teiv-image.yml` publishes; it needs `teiv.kafka.bootstrapServers` (the chart brings no broker) and fails the render without it, and adds NetworkPolicies that admit only smo-teiv's own pods to its database and only TE&IV's to its API. Memory: about 2 GiB measured at 1,000 cells for the four containers (budget 3 GiB; the workflow "TE&IV load" checks it). The facade that makes TE&IV usable is plan task S3.19.
