### `rapp-mgmt`

| Variable | Default | Secret | Read in | What it does |
|---|---|---|---|---|
| `RAPP_MGMT_REQUIRE_SME_REGISTRATION` | `false` |  | `rapp-mgmt/app/provisioning.py` | `true`, `1`, `yes` or `on`: rApp Management refuses an instance's bootstrap (it stays DEPLOYING; 503 when SME does not answer, 502 when it refuses) unless every SME declaration of its package (`Files/Sme/providers`, `serviceapis`) is registered. Default `false`: the registration is best-effort and a failure is ignored. `deploy/helm/smo/values-production.yaml` turns it on. Call flow 01d. |
| `RAPP_MGMT_SECRET_ROTATION_DAYS` | `0` |  | `docker-compose.yml`, `rapp-mgmt/app/rotation.py` | Read by the rApp Management worker (`rapp-mgmt-worker`, `SEC-15.19`): rotate the secret of a RUNNING rApp instance (with a registered operator API) once it is older than this many days, the same renewal as Re-send credentials. Default `0` (also unset, negative or not a number): no automatic rotation, nothing is read or written. An instance whose workload cannot be reached is not rotated and is tried again at the next run; with `RAPP_CREDENTIAL_DELIVERY=kubernetes` nothing is rotated. A number of days, not a secret. `docs/SECRETS.md`. |
| `RAPP_MGMT_SECRET_ROTATION_MAX_PER_RUN` | `10` |  | `docker-compose.yml`, `rapp-mgmt/app/rotation.py` | The most instances one run of the automatic secret rotation rotates, oldest secret first (default `10`, at least `1`), so instances that fall due together are rotated over several runs. Only used while `RAPP_MGMT_SECRET_ROTATION_DAYS` is above 0. A count, not a secret. |
| `RAPP_MGMT_SECRET_ROTATION_SWEEP_SECONDS` | `900` |  | `docker-compose.yml`, `rapp-mgmt/app/tasks.py` | How often the rApp Management worker looks for instances whose secret is due (default `900`, at least `1`), across all worker replicas. Read once at the worker's start. Only used while `RAPP_MGMT_SECRET_ROTATION_DAYS` is above 0. Seconds, not a secret. |
