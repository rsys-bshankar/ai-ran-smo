# The third-party images CI and the product pull, and where each is mirrored on GHCR (docs/MIRROR.md).
#
# One line per image: `source | digest | mirror | note`, fields separated by `|`, blank lines and `#` lines ignored.
#   source  the reference as the repository writes it, WITHOUT the digest: `repository[:tag]` (a tag is required unless the digest is given)
#   digest  `sha256:<64 hex>` as pinned in the repository today, or `-` when the repository pins none (then the note says why, and the mirror
#           copies whatever the tag resolves to when it runs)
#   mirror  the image's name under ghcr.io/<owner>/<repo>/mirror/, or `-` for an image that is not copied (the note says why)
#   note    free text; required when the digest is `-` or the mirror is `-`
#
# The mirror's tag is the source's tag (`latest` when the source names none). Two sources that differ only in tag share one mirror name,
# so they are one GHCR package.
#
# This file is the source of truth for scripts/mirror_images.py (validate, copy, verify) and is held in step with the pins by
# tests_integration/test_image_mirror_list.py: a pin in docker-compose.yml, deploy/helm/smo/values.yaml, deploy/helm/smo/ci, a Dockerfile, a
# workflow or a script that is missing here, or has another digest, fails that test. A Dependabot bump of a pin therefore needs the same edit here.
# CI takes these pins from here: scripts/ci_mirror.py setup exports each row as a variable SMO_IMAGE_<NAME> (the mirror reference when it answers, this row's
# `source@digest` otherwise), writes the compose override and the Helm values, and the workflows hold no digest of a row that is mirrored. The files an operator
# runs (compose, chart, Dockerfiles) keep naming the upstream images (docs/MIRROR.md).
# A `-` digest stays legal for a reference the repository cannot pin (the note says why), but there is none today and the drift test holds the set empty.
