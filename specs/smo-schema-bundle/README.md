# Converged SMO (O-RAN + 3GPP Rel-18 SBMA) Schema, YANG & Database Bundle

This bundle provides the complete High-Level Design (HLD) and Low-Level Design (LLD) interface contracts, O1 NETCONF/YANG modules, database DDL scripts, and sample rApp payloads for the **O-RAN + 3GPP Service Management and Orchestration (SMO)** platform.

## 2. How to Use This Bundle in Your Engineering Workflow

### Step 1: Validate & Generate Microservice Stubs from the Modular OpenAPI 3.0 Bundle
All module OpenAPI specs in `openapi/modules/` inherit the generic `createMOI`, `getMOIAttributes`, `modifyMOIAttributes`, and `deleteMOI` operations from `openapi/common/ts28532-ProvMnS-base.yaml` via `$ref`.

1. **Validate the OpenAPI specs:**
   ```bash
   npx @redocly/cli lint openapi/common/*.yaml openapi/modules/*.yaml
   ```
2. **Bundle a module spec into a standalone file (resolving `$ref` across `common/`):**
   ```bash
   npx @redocly/cli bundle openapi/modules/so-smos-ts28312-intent.yaml -o dist/so-smos-bundled.yaml
   ```
3. **Generate Spring Boot / Go / FastAPI server stubs for `lib-smo-mns-common`:**
   ```bash
   openapi-generator-cli generate \
     -i openapi/common/ts28532-ProvMnS-base.yaml \
     -g python-fastapi \
     -o generated/lib-smo-mns-common
   ```

### Step 2: Validate & Compile O1 YANG Modules for RAN NF OAM
The YANG modules in `yang/common/` and `yang/o1-ran/` define the Southbound O1 NETCONF datastore schema for `RAN NF OAM`.

1. **Validate YANG syntax and tree hierarchy using `pyang`:**
   ```bash
   pyang -p yang/common -p yang/o1-ran -f tree yang/o1-ran/*.yang
   ```
2. **Validate the sample O1 NETCONF `<edit-config>` payload using `yanglint`:**
   ```bash
   yanglint -p yang/common -p yang/o1-ran \
     yang/common/_3gpp-common-managed-element.yang \
     yang/o1-ran/_3gpp-nr-nrm-gnbdufunction.yang \
     yang/o1-ran/_3gpp-nr-nrm-nrcelldu.yang \
     yang/o1-ran/_3gpp-nr-nrm-nrcellrelation.yang \
     examples/o1_netconf_edit_config_nes_mro.xml
   ```

### Step 3: Initialize the SMO Common & Per-Module Databases
The SMO uses a hybrid database design:
- **Common Shared Databases (`db/01_common_shared_databases.sql`):** Canonical NRM + TE&IV Graph (`common_teiv_nrm`) and DME Telemetry/Alarm Lakehouse (`common_dme_telemetry`).
- **Per-Module Isolated Schemas (`db/02_per_module_schemas.sql`):** `so_smos`, `sa_smos`, `ran_oam`, `dme_ts`, `mdaf`, `aiml_wf`, `rapp_mgmt`, and `sme_capif`.

Run against PostgreSQL 15+ (with TimescaleDB optional for hypertables):
```bash
psql -U postgres -d smo_platform -f db/01_common_shared_databases.sql
psql -U postgres -d smo_platform -f db/02_per_module_schemas.sql
```

### Step 4: Test End-to-End Playbook Calls (NES & MRO rApps)
Use the JSON payloads in `examples/` to test the complete loop:
1. Onboard the rApp descriptor: `examples/rapp_nes_asd_package.yaml` -> `rAppMgmt`.
2. Submit Operator Level-1 Intent to SO SMOS:
   ```bash
   curl -X PUT "https://smo.operator.internal/so-smos/ProvMnS/v18/Intent=intent-nes-cluster12-001" \
     -H "Content-Type: application/json" \
     -d @examples/nes_level1_goal_intent.json
   ```
3. Simulate rApp Level-2 Actuation Intent over R1 to SO SMOS:
   ```bash
   curl -X PUT "https://r1.smo.internal/so-smos/ProvMnS/v18/Intent=intent-l2-nes-actuation-20261029-01" \
     -H "Authorization: Bearer <CAPIF_OAUTH2_TOKEN>" \
     -H "Content-Type: application/json" \
     -d @examples/nes_level2_actuation_intent.json
   ```

### Step 5: Test High-Scale DME Telemetry Batch Ingestion (`RAN NF OAM -> DME`) & Matrix Query (`rApp <-> DME`)
1. **RAN NF OAM publishes 1 normalized ROP batch per gNB (`ManagedElement`) every 15 minutes to DME:**
   - Stored in `common_dme_telemetry.dim_cell` + wide `pm_rop_ts28552` (`counters JSONB`) and `kpi_rop_ts28554` (`kpis JSONB`), reducing row volume by **1,000x** compared to narrow 1-row-per-counter EAV tables.
   - Test SQL batch upsert function directly in PostgreSQL:
     ```sql
     SELECT common_dme_telemetry.fn_upsert_oam_rop_batch(
       '{"managedElementDn":"SubNetwork=BLR_12,ManagedElement=gNB_104","subNetworkDn":"SubNetwork=BLR_12","ropEndTime":"2026-10-30T14:15:00Z","granularityPeriodSec":900,"cells":[{"cellDn":"SubNetwork=BLR_12,ManagedElement=gNB_104,GNBDUFunction=1,NRCellDU=Cell_1","counters":{"RRU.PrbTotDl":24.8,"PEE.AvgPower":710.5}}]}'::jsonb
     );
     ```
2. **rApp subscribes or queries a multi-cell, multi-metric matrix over R1:**
   - See `examples/dme_oam_rop_batch_and_rapp_matrix.json` for the complete `POST /r1/dme/v1/dataJobs` subscription payload, the consolidated per-ROP push payload, and the `POST /r1/dme/v1/query` historical matrix response.
